1. 目标与非目标

要达成

  • 把抽象方法拆成可勾选的小任务，降低「不知道下一步」。
  • 用站一 → 站二 → 站三递进，先跑通流程再追求流量。
  • 每周有少量新知进站，形成学习节奏，而不是一次塞完。
  • 第一版尽量零部署：下载 HTML，浏览器打开即可打卡。

不做（第一版）

  • 不做账号登录、云端同步、排行榜社交。
  • 不替你自动建站、注册域名、申请 AdSense。
  • 不复刻哥飞付费社群生意；只用公开方法骨架 + 全网公开资料。
  • 不做收益承诺或「几天赚多少」话术。

2. 用户故事

作为学习者

打开页面就能看到「当前关」和今日可做的 1～3 个任务；勾完有反馈，不会丢进度。

作为忙时的你

周一看到「本周补给」两三条摘要即可；没空就跳过，不影响主线关卡。

作为 Grok Bot

每周只改数据数组、必要时发聊天摘要；不碰你的打卡进度。

作为后续升级

若以后要部署到公网，同一套关卡数据可迁到静态托管，进度仍可先放浏览器本地。

3. 核心循环

游戏感来自「短反馈」，不是复杂数值。

flowchart LR A[看当前关任务] --> B[线下实践] B --> C[勾选完成] C --> D[加 XP / 连击] D --> E{本关必做完成?} E -->|否| A E -->|是| F[解锁下一关] F --> A G[每周补给] -.-> A
反馈三件套：勾选即时勾上 + 轻微 XP 增长 + 通关时解锁下一章（可选轻提示音/横幅，不做花哨特效刷屏）。

4. 关卡地图（主线）

关卡目标必做示例通关标准
序章 · 定方向 选站类型 + 一站一词 写下站类型；写下本站主词；读完「不做什么」 方向备忘写好
第1关 · 站一 跑通全流程 域名/托管/上线；提交 GSC；品牌词能搜到 谷歌能搜到自己的站名
第2关 · 站二 低竞争有搜索量 用搜索+intitle:选词；做页；外链/发现；追排名 目标词有曝光，并朝首页推进
第3关 · 站三 更高搜索量 + 内页 扩长尾内页；内链回首页；持续看 GSC 多页有收录与点击趋势
第4关 · 变现入门 流量→变现意识 了解 AdSense 资格；准备合规页；建立看数习惯 知道门槛与自己的变现路径选项
第5关 · 放大 模板 / 多站思路 复盘模板可复用点；规划下一站选题（先学不急量产） 有下一站计划草案

每关 3～6 个任务；可标 1 个「可选支线」（如提前读某篇公开文），不挡通关。

5. 信息架构与界面

单页区块（自上而下）

  1. 顶栏 HUD：当前关名、XP 条、连击天数、重置进度（需二次确认）。
  2. 关卡地图：横滑或纵向列表；未解锁灰显；当前关高亮。
  3. 任务板：当前关 checklist；展开可见「做什么 / 工具 / 完成标准 / 坑」。
  4. 本周补给：最新 1～3 条置顶，历史可折叠。
  5. 资料柜：链到已有 playbook / 公开文链接（只摘要，不整篇搬运）。

视觉原则

  • 高对比：正文近黑 #0b1220，链接深蓝 #1d4ed8 / #1e3a8a，避免浅蓝底浅字。
  • 移动端优先；无障碍：勾选可键盘操作，焦点可见。
  • 第一版尽量零 CDN，离线也能打卡（补给链接需联网打开外站）。

6. 数据与进度

写死在文件里（我改）

CHAPTERS 关卡与任务文案；WEEKLY_UPDATES 每周补给条目。

存在浏览器里（你改）

localStorage：已完成任务 id、XP、连击、解锁进度。换设备会丢，属第一版取舍。

边界：每周更新只允许追加/修剪 WEEKLY_UPDATES，禁止清空你的打卡进度字段。 
localStorage key: gefei-quest-progress-v1

  "done": ["q-1-1", "q-1-2"],
  "xp": 120,
  "streak": 3,
  "lastCheckIn": "2026-10-16",
  "unlocked": ["prologue", "stage1"]
}

7. 每周补给机制

sequenceDiagram participant Cron as 周一例行 participant Bot as Grok Bot participant File as index.html participant You as 你 Cron->>Bot: 触发「每周知识补给」 Bot->>Bot: 全网扫公开 SEO/出海新知 alt 有值得加的 Bot->>File: 追加 WEEKLY_UPDATES Bot->>You: 聊天摘要 + 附更新文件 else 无增量 Bot-->>You: 保持安静 end
  • 节奏：每周一上午（上海时间）例行；无新料不打扰。
  • 体量：每次 1～3 条；每条标题 + 2～4 句摘要 + 可选链接。
  • 来源：谷歌官方文档更新、公开实操文、部署/广告合规要点；不贴大段原文。
  • 状态：例行已创建但已暂停，等你认可设计并开工后再开启。

8. MVP 范围（一旦开工）

  • 单文件 index.html：HUD + 地图 + 任务勾选 + 补给面板
  • 进度 localStorage 持久化 + 重置
  • 序章～第3关内容可玩；第4～5关可先放简化任务
  • 播种 2～3 条补给样例
  • 简短 README：怎么打开、进度存在哪、怎么跟我说「我通关了」
  • 开启每周一补给例行

预估：一次集中开发即可出可用第一版（在现有 playbook 内容上改编）。

9. 后续迭代（不做进 MVP）

版本加什么何时值得做
v1.5导出/导入进度 JSON；暗色模式换设备或眼睛疲劳时
v2静态托管（Cloudflare Pages）+ 同一套页面你想手机随时打开固定网址
v2.5可选「提交证据」备注框（URL/截图说明，仍本地）想更认真复盘时
v3多站并行进度 / 模板库走出新手村之后

10. 风险与原则

  • 游戏化别过头：XP 只是反馈，通关标准对齐真实 SEO 结果（收录、曝光），避免「只点勾、不建站」。
  • 合规：AdSense、托管条款（如部分免费套餐非商用）在关卡文案里写清。
  • 版权：补给只摘要公开信息并附链接，不整页搬运。
  • 进度易丢：第一版依赖本机浏览器；重要节点可让你把完成情况跟我说一声做备份备忘。
建议决策：认可本设计后，再开工做「本地单页关卡打卡」MVP，并恢复周一补给例行。若要改关卡数量、去掉 XP、或改成先部署再打卡，直接说偏好即可。
