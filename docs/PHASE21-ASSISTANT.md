# Phase 21 · 问 AI 助手 + 下一步引导

目标：用户在任何页面都能随手提问，且始终知道「下一步做什么」。保持页面短、高对比、风格一致；存档只做增量（`gefei-quest-save-v1` 不改名、不删字段）；不编数据、不承诺收益。

## A · 全站助手「问 AI」（T187）
- 每个路由右下角浮动按钮「问 AI」。390px 时位于底部标签栏之上，不遮挡；与「回到顶部」按钮不重叠。
- 点击打开面板：桌面右侧面板约 380px，移动端全屏抽屉。有关闭按钮，Esc 关闭；打开时焦点进入输入框，关闭后焦点回到浮动按钮；Tab 在面板内循环。
- 上下文：系统提示包含当前路由、页面标题、存档进度摘要（等级、已完成任务数、候选词数、站点数等，只用存档里的真实数据）。
- 快捷问题：按当前页面给出 2–4 个 chip（如 #war-keywords：「怎么判断一个词值不值得做？」），未定义的页面用通用 chip。
- 回答用 `QuestAI.md()` 渲染（已转义、链接白名单）。
- 自定义服务商可用（`QuestAI.ready()`）时：复用 `QuestAI.chat()` 流式输出，带停止按钮。`chat()` 只做增量扩展（如可选 `opts.system`），不复制请求逻辑。
- 未连接 AI（Grok Bot 模式或没配置）时：离线模式，在站内资料（guides-data.js、首页 FAQ、hints.js、platform-data.js、工具模板）里按关键词匹配，返回前 3 条片段，每条带跳转到对应路由的链接；标注「站内资料检索（未连接 AI）」，并附「去 AI 设置」链接 #me-ai。没有匹配时如实说明没找到，不编内容。
- 对话只存 sessionStorage `gefei-quest-chat-v1`；「清空对话」按钮。
- 新 JS 文件加入 sw.js 预缓存。

## B · 首页「下一步」卡片（T188）
- 位于首屏之后，单张卡片（不是功能网格），保持首页先介绍。
- 根据存档在 学习→实施→赚钱 中算出唯一推荐动作（如：完成第一课 → 选一个词 → 在「我的站点台账」登记站点 → 发布 → 看数据复盘），一个主按钮直达对应路由。
- 新访客：「从『新手引导』开始」→ #start。

## C · 工具页目标 + 下一步（T189）
- 已有的页面提示条增加一行目标；有意义的页面显示 3 步小进度（按存档计算是否完成）。
- 页面底部「下一步 →」按钮，指向 学习→实施→赚钱 流程中的下一页。顺序在一个共享映射中定义（hints.js），全站复用。
